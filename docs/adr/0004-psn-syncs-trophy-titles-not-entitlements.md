# PSN 同步取獎盃清單而非持有清單

PSN 沒有官方公開 API，能拿到的清單有三種語意：獎盃清單（玩過的）、購買持有清單（買下的）、最近遊玩（太少）。我們取**獎盃清單**——它的識別碼與端點行為有社群長期驗證，帶得出完成度與最後遊玩時間，在「數位遊戲」品類裡與 Steam 的遊玩時數結構對得起來；持有清單要打商店的未公開 GraphQL，且混入大量 demo、beta 與每月領取的雜訊。

代價是收藏的「擁有」被放寬了：透過 PS Plus 遊戲庫玩過但未購買的遊戲會被建成品項，退訂後你其實不擁有它；反過來，買了從未開啟、或根本沒有獎盃的遊戲不會出現。

## Considered Options

- **購買持有清單（Entitlements）**：語意最接近「擁有」，但端點未公開、回應含大量非遊戲項目，且仍需同一套 NPSSO 認證——付出的代價一樣，拿到的資料更難用。
- **最近遊玩**：只有最近數十款，做不出收藏。

## Consequences

- 唯一拿得到的識別碼是 `npCommunicationId`（`NPWR12345_00`），獎盃清單端點**不回傳** CUSA/PPSA。IGDB 的 `external_games` 沒有索引 `npCommunicationId`，所以 **PSN 品項沒有任何自動的 IGDB 補完路徑**——不是懶得做，是沒有鍵可以 join。要補完得手動填 `igdbId`，填上之後既有補完路徑原樣運作。
- 簡介欄位 `trophyTitleDetail` 是 PS3/PS4/Vita 的遺留欄位，**PS5 遊戲拿不到簡介**。加上前一點，收藏會分成資訊豐富的 Steam 那半、與只有品名與圖示的 PSN 那半。
- `npCommunicationId` 識別的是**獎盃組**而非遊戲本身。同一款遊戲的區域版本可能有不同的獎盃組，會成為不同品項。
- 認證是 NPSSO（瀏覽器手動取得，約兩個月過期）換 access token（數小時）。我們只儲存 NPSSO，每次同步當場換發、用完即棄，不保存 refresh token——同步是低頻的手動批次操作，省下的那不到一秒買不起一套換發／輪替／失敗處理的狀態機。
- NPSSO 過期是**必然會發生且重試無用**的失敗，與 `CONTEXT.md` 中「值得重試」的失敗語意不同。我們不為它新增狀態分類，改由錯誤訊息明確指出需要重新取得 NPSSO。這則訊息的措辭是這個決定的驗收條件。
