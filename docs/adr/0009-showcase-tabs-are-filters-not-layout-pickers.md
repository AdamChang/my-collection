# ADR-0009：精選頁的展示模式頁籤是篩選器，不是版型選擇器

- 狀態：已接受
- 日期：2026-08-06
- 相關：[ADR-0007](0007-showcase-display-mode-and-collage-is-unfiltered.md)（本 ADR 不推翻它，只改變呈現方式）、[ADR-0008](0008-storage-location-never-public-rating-opt-in.md)

## 背景

ADR-0007 落地後，`/showcase` 與 `/p/:slug` 兩頁都把 Hero、Stats、Collage 三個展示分區**同時疊在列表網格上方**。實際使用後，一頁之內出現四種視覺語言（大圖輪播、滿版成就看板、拍立得拼貼、卡片網格），彼此爭奪注意力，使用者反映「過於混亂」。

需求是讓使用者自行切換想看的展示模式。但「切換模式」有兩種截然不同的實作語意，選錯會讓 ADR-0007 剛落地的資料模型變成死欄位。

## 決定

### 一、頁籤是篩選器

頁籤切換的是**看哪一群品項**，不是**用什麼版型看同一群品項**。

- 「焦點展品」頁籤顯示 `effectiveDisplayMode === 'Hero'` 的品項，「遊戲成就」頁籤顯示 `=== 'Stats'` 的品項。
- 「拼貼牆」與「列表」兩個頁籤顯示全部精選品項，不篩選——延續 ADR-0007 對 Collage 的規定。
- `Item.DisplayMode` / `Category.DefaultDisplayMode` 的語意完全不變：仍然由品項（或其品類）決定自己屬於哪一種展示，使用者只是選擇要看哪一群。

四個頁籤依序為：拼貼牆（預設）、焦點展品、遊戲成就、列表。

### 二、被否決的替代方案：頁籤作為版型選擇器

另一個讀法是「點焦點就把**全部**精選品項用 Hero 版型呈現」。否決理由：

- `Item.DisplayMode` 與 `Category.DefaultDisplayMode` 會立刻失去作用，ADR-0007 的整個資料模型變成只剩「決定預設開哪個頁籤」的參考值。
- 版型與資料是耦合的。Stats 版型渲染的是 `playtimeForever` 與 `psnProgress`，這兩個欄位只有數位遊戲有。把公仔模型套進 Stats 版型會得到一張只有背景圖、沒有任何數據的空看板——不是「另一種呈現」，是壞掉的呈現。

這條很容易被後人誤讀成「使用者想選版型，我們卻只給了篩選」而改回去，所以特別記錄。

### 三、公開分享頁與內部頁行為一致

`/p/:slug` 一併改為相同的四頁籤，共用同一個頁籤元件與同一組 query param。

原本的建議是只改內部頁、公開頁維持疊加式長頁面，理由是訪客沒有探索模式的動機，多一層點擊只會流失。**這個建議被明確否決**，採用一致性優先：

- 兩頁共用 `showcase-sections/` 底下的同一組元件，排版一旦分歧，往後每次改動都要同時維護兩種版面，而兩者的差異只有「公開頁少幾個欄位」這種資料層面的事。
- 分享出去的頁面是收藏的門面，跟自己看到的長得不一樣會讓分享者無法預期訪客看到什麼。

分享者指定「訪客預設落在哪個頁籤」的能力**不做**。`ShareLink` 已有 `IncludeRating`、`CollageSlotCount` 這類展示設定，要加 `DefaultView` 是同一個模式，但那是為假想需求先付 Domain 層的代價；等真的有人要求再加。

## 後果

- 「該模式 0 件」的頁籤停用並顯示 0，不隱藏——版面不跳動，且使用者看得到自己還沒用到的展示模式，才有動機去品項頁設定。
- 頁籤的數字與啟用狀態必須是穩定的事實，因此**資料全部載入完成才渲染頁籤列**。原本列表底下的「載入更多」按鈕拿掉，改為自動續抓至 `total`（安全上限 2000 件）。若不這麼做，第一批資料回來時焦點頁籤可能顯示 0 且被停用，續抓完又啟用，頁籤列會閃動。
- 切走的頁籤以 `@if` 銷毀，Hero/Stats/Collage 的輪播計時器隨之停止；切回來時輪播從第一張開始。這保留了 ADR-0007 實作時「計時器不得卡住 `ApplicationRef.whenStable()`」的既有保證。
- hover 中央預覽只存在於內部頁的列表頁籤。它會顯示 `storageLocation`，依 ADR-0008 這個欄位永不進公開頁——`toPublicShowcaseDisplayItem` 把 `storageLocation` 寫死 `null` 的那道防線必須保留。
