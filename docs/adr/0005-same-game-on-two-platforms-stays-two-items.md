# 同一款遊戲在不同平台是兩筆品項

品項的 upsert 鍵是 `(ownerId, provider, externalId)`，且 `ExternalRef` 是單數——一筆品項只掛得住一個來源。接上 PSN 之後，同一款遊戲若 Steam 與 PlayStation 都有，收藏裡就是兩筆。我們接受這個結果，不做跨來源合併。

理由是收藏的語意本來就是「我擁有這個東西的這一份」：實體收藏不會把 PS5 光碟與 Switch 卡帶算成同一筆，數位的沒有理由不同。合併則要改寫入路徑的核心鍵、補完的定址方式（`FetchByExternalIdsAsync` 假設一個品項對應一個外部識別碼），並引入「合併後品名由誰說了算」這個新的擁有權問題——為了視覺上不重複而動核心，投報率不對。

## Consequences

- 清單上會出現同名的兩筆，因此 `platform` 不是可有可無的欄位，而是**唯一能分辨它們的東西**。這也是它在兩個遊戲品類都設 `showOnCard` 的原因。
- 既有的 `platform`（「平台／商店」，我這一份在哪）與 IGDB 寫入的 `platforms`（「發行平台」，這款遊戲發行於哪些平台）是兩個不同的概念，只差一個字母。不要合併，也不要讓任何來源交叉寫入。
- 同步開始寫 `platform` 之後，它從純手動欄位變成來源會寫的欄位。採**軟寫入**：品項已有值就不動。使用者可能刻意填了「PS5 光碟版」這類只有他自己知道的區別，而同步端知道的永遠比手動填的粗；無條件覆蓋會在下一次同步靜默改掉它。
- 代價是既有品項若曾手動填過不一致的寫法，永遠不會被統一，清單上會混著兩種格式。
