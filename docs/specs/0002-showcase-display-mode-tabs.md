# 精選頁改用展示模式頁籤，並為列表加上滑鼠停留預覽

> **狀態：已實作完成（2026-08-06）**，分支 `feat/showcase-tabs-and-hover-preview`。
> 這份規格是**事後整理的參考文件**，不是待辦工作——不要當成 backlog 交給 agent 實作。
> 相關文件：[ADR-0009](../adr/0009-showcase-tabs-are-filters-not-layout-pickers.md)、
> [設計文件](../superpowers/specs/2026-08-06-showcase-tabs-and-hover-preview-design.md)、

## Problem Statement

我打開精選頁想看自己的收藏，但一頁之內同時出現四種完全不同的視覺語言：焦點展品的大圖輪播、遊戲成就的滿版看板、拼貼牆的拍立得照片、還有底下的列表網格。它們彼此爭奪注意力，我沒辦法專心看任何一種，整頁讀起來很混亂。

另外兩個問題：遊戲成就的看板高度只有 16rem，背景圖被壓得很扁，完全沒有成就展示該有的份量；而列表網格的卡片圖太小，我想確認某件收藏的細節時，得點進品項詳細頁才看得到完整圖片和欄位，看完再退回來——想連續比對好幾件時特別煩。

## Solution

把四種展示改成使用者自己切換的頁籤，一次只專心看一種。

頁籤依序是拼貼牆（預設）、焦點展品、遊戲成就、列表。切換狀態記在網址上，所以可以把「我只想看焦點展品」這個視圖存成書籤或分享出去。沒有品項的頁籤會顯示 0 並停用，讓我知道還有這個展示模式可用、但我還沒把任何品項設定成它。

遊戲成就看板放大到桌機約 40rem，獨佔一整頁時才有沉浸感。拼貼牆從 4 張小卡改成 8 張大卡置中排列，因為它現在是打開頁面的第一眼。

在列表頁籤裡，滑鼠停在任何一張卡片上約 0.2 秒，畫面正中央就浮出那件收藏的完整大圖與欄位，移開就消失——不必點進詳細頁，也不必退回來。

公開分享頁使用完全相同的四個頁籤，這樣我分享出去的畫面跟自己看到的一致，不會有意外。

## User Stories

1. 作為收藏者，我想一次只看一種展示模式，這樣版面不會四種視覺語言互相干擾。
2. 作為收藏者，我想在打開精選頁時先看到拼貼牆，這樣有個賞心悅目的門面。
3. 作為收藏者，我想切到焦點展品頁籤只看公仔模型與珍藏卡，這樣能專心欣賞大圖。
4. 作為收藏者，我想切到遊戲成就頁籤只看數位遊戲，這樣遊玩時數與獎盃完成度不會跟公仔混在一起。
5. 作為收藏者，我想切到列表頁籤看到全部精選品項，這樣要找特定一件時有完整清單。
6. 作為收藏者，我想在拼貼牆看到全部精選品項而不只是某一種展示模式的，這樣預設是 List 的音樂專輯與電影光碟不會精選了也白精選。
7. 作為收藏者，我想在每個頁籤上看到該模式的品項數，這樣切過去之前就知道裡面有沒有東西。
8. 作為收藏者，我想讓沒有品項的頁籤呈現停用而不是消失，這樣我知道還有這個展示模式可以用，會想去品項頁設定它。
9. 作為收藏者，我想讓頁籤列的數字在出現時就是最終值，這樣不會邊載入邊跳動，也不會讓我點到一個正要變成可用的頁籤。
10. 作為收藏者，我想把「只看焦點展品」這個視圖存成書籤，這樣下次直接開到那裡。
11. 作為收藏者，我想在重新整理後停在同一個頁籤，這樣不會每次都被丟回拼貼牆。
12. 作為收藏者，我想讓切換頁籤不要塞爆瀏覽記錄，這樣按上一頁是回到前一個真正的頁面，不是倒退一個頁籤。
13. 作為收藏者，我想在網址被亂改時退回拼貼牆，這樣不會看到一片空白以為壞了。
14. 作為收藏者，我想在書籤指向的頁籤已經沒有品項時自動退回拼貼牆，這樣不會停在一個停用又空白的頁籤上。
15. 作為收藏者，我想讓切走的頁籤停止輪播，這樣看不見的分區不會在背景燒效能。
16. 作為鍵盤使用者，我想用 Tab 鍵一次就進入頁籤列，這樣不必逐一跳過四顆按鈕。
17. 作為鍵盤使用者，我想用左右方向鍵在頁籤間移動，這樣符合我對頁籤元件的既有預期。
18. 作為鍵盤使用者，我想讓方向鍵跳過停用的頁籤，這樣不會停在一個按了沒反應的地方。
19. 作為鍵盤使用者，我想用 Home 與 End 直接跳到第一個與最後一個可用頁籤，這樣長列表不必一路按過去。
20. 作為鍵盤使用者，我想在切換頁籤後焦點跟著移到新頁籤，這樣接續操作不會斷掉。
21. 作為螢幕閱讀器使用者，我想讓頁籤列正確宣告自己是 tablist 並標示目前選中項，這樣我知道自己在哪。
22. 作為收藏者，我想讓遊戲成就看板夠高，這樣獨佔一整頁時下方不會留一大片空白。
23. 作為手機使用者，我想讓成就看板在窄螢幕自動收斂，這樣不會變成一整屏的黑底圖。
24. 作為收藏者，我想讓拼貼牆的拍立得夠大，這樣它作為第一眼有足夠的視覺重量，而不是一排縮圖。
25. 作為收藏者，我想讓拼貼牆置中排列，這樣寬螢幕右側不會空一大塊。
26. 作為收藏者，我想在列表頁籤把滑鼠停在卡片上就看到完整大圖，這樣不必點進詳細頁再退回來。
27. 作為收藏者，我想在預覽裡看到品類欄位、入手日期、入手價格、存放位置與評分，這樣判斷一件收藏所需的資訊一次到齊。
28. 作為收藏者，我想讓預覽不顯示描述，這樣長文不會把圖片壓掉一大半。
29. 作為收藏者，我想讓預覽的圖片完整不裁切，這樣直式的公仔與卡牌看得到全貌。
30. 作為收藏者，我想讓預覽的外框尺寸固定，這樣滑過比例差很多的品項時畫面不會劇烈變形。
31. 作為收藏者，我想讓圖片留白處用同一張圖的模糊放大填滿，這樣不會出現生硬的黑邊。
32. 作為收藏者，我想讓預覽先顯示已經載過的小圖、原圖載完再換上，這樣不會空等一拍。
33. 作為收藏者，我想在滑鼠快速滑過整排卡片時不要瘋狂閃出預覽，這樣掃視清單不受干擾。
34. 作為收藏者，我想在游標還沒停滿就移到別張卡片時不要閃出前一張的預覽，這樣看到的永遠是當下那件。
35. 作為收藏者，我想讓預覽消失後仍能直接點擊底下的卡片進入詳細頁，這樣預覽不會擋路。
36. 作為收藏者，我想讓沒有圖片的品項一樣浮出預覽，這樣不會以為某些卡片壞掉了。
37. 作為手機使用者，我想讓滑鼠停留預覽完全不觸發，這樣長按手勢不會跟系統選單打架。
38. 作為分享者，我想讓公開頁與內部頁使用相同的頁籤，這樣我知道訪客看到什麼。
39. 作為分享者，我想讓公開頁繼續套用我設定的拼貼格數，這樣分享連結的個別設定不被覆蓋。
40. 作為分享者，我想確保存放位置在任何頁籤下都不會出現在公開頁，這樣別人看不到我的收藏放在家裡哪一櫃。
41. 作為訪客，我想在分享頁看到跟收藏者一樣的四個頁籤，這樣瀏覽體驗一致。

## Implementation Decisions

**頁籤語意是篩選器，不是版型選擇器（ADR-0009）。** 切換頁籤換的是「看哪一群品項」，不是「用什麼版型看同一群品項」。品項的展示模式（`List` / `Hero` / `Stats`）與品類的預設展示模式語意完全不變，ADR-0007 未被推翻。被否決的替代讀法是「點焦點就把全部精選品項用 Hero 版型畫」——那會讓展示模式的資料模型立刻失效，而且遊戲成就的版型渲染的是遊玩時數與獎盃完成度，把公仔套進去只會得到一張空看板。

**新增一個共用的頁籤列模組**，內部精選頁與公開分享頁共用。介面接受一組頁籤（識別碼、標籤、品項數）與目前選中的識別碼，對外送出使用者選擇的識別碼。品項數為 0 即停用。鍵盤行為做完整的 WAI-ARIA tabs pattern：方向鍵、Home/End、roving tabindex，且一律跳過停用頁籤。做一半的 tablist（有 role 沒方向鍵）對螢幕閱讀器比完全沒有 role 更糟。

**新增一個滑鼠停留預覽模組**，純呈現。它接受一個展示品項與一個可選的原圖網址，沒有品項就什麼都不畫。**進場延遲刻意不做在這個模組裡**——延遲屬於「何時該顯示」，是呼叫端的職責，分開才能各自測試。

**頁籤狀態走網址查詢參數**，四個合法值對應四個頁籤。專案的路由設定已啟用元件輸入繫結，所以查詢參數直接綁到元件輸入，不需要注入路由服務去讀。寫回時合併既有參數並取代瀏覽記錄。

**正規化分兩層**：語法上非法的值退回拼貼牆；語法合法但該頁籤品項數為 0 時（書籤存了焦點展品、之後所有焦點品項都被取消）也退回拼貼牆。

**精選品項一次載滿才渲染頁籤列。** 原本的「載入更多」按鈕移除，改為自動續抓至總數。終止條件必須同時看「這一頁沒拿到任何東西」與一個硬上限（2000 件），只看「已載入數 < 總數」的話，後端若謊報總數就會無限發請求。這麼做是因為頁籤的數字與啟用狀態必須是穩定的事實。被否決的替代方案是讓每個頁籤各自向後端分頁——精選品項的量級是幾十件，為一個大概永遠不會觸發的規模去動 API 不划算。

**切走的頁籤整個銷毀**，不是隱藏。三個展示分區各自有輪播計時器，隱藏會讓它們在背景繼續跑並持續消耗 GPU。銷毀的代價是切回來時輪播從第一張開始，但輪播沒有「進度」的概念，使用者不會記得停在第幾張。

**滑鼠停留預覽只存在於內部精選頁的列表頁籤。** 延遲 200ms、淡入 150ms。浮層本身不接收滑鼠事件，所以游標永遠不會「進入」浮層，也就不會卡住預覽或擋住底下卡片的點擊。整套行為關在「裝置支援 hover」的媒體查詢裡。

**預覽的圖片用固定 16:10 外框加完整縮放（不裁切）**，留白處用同一張圖模糊放大填滿。被否決的替代方案是讓外框隨圖片比例伸縮——收藏裡直式的公仔卡牌與寬扁的遊戲頭圖比例差極遠，外框會隨游標移動劇烈變形。

**圖片漸進式替換**：先用列表已經快取的卡片尺寸圖（480px），呼叫端在延遲期間就開始預載原圖（1600px），載完才傳給預覽模組替換。預載完成是非同步的，回來時游標可能早已移到別張卡片，所以必須比對當下停留的品項識別碼，否則會把前一張的原圖套到現在這張上。沒有本地圖片、只有外部來源網址的同步品項沒有原圖版本，直接沿用既有的網址挑選規則。

**預覽顯示的欄位沿用焦點展品側欄那一組，但拿掉描述**：品類設定為「顯示於卡片」的欄位，加上入手日期、入手價格、存放位置、評分。欄位以自動換欄的網格壓在圖片下緣。不設欄位數上限——那些欄位是使用者自己在品類設定裡勾選的，程式再砍一次等於讓那個勾選失效。

**公開分享頁與內部頁行為一致（ADR-0009）**，共用同一個頁籤模組與同一組查詢參數值。原本的建議是只改內部頁、公開頁維持長頁面，理由是訪客沒有探索模式的動機；這個建議被明確否決，理由是兩頁共用同一組展示分區模組，排版一旦分歧，往後每次改動都要維護兩種版面。**分享者指定訪客預設頁籤的能力不做**——那是為假想需求先付 Domain 層的代價。

**存放位置永不進公開頁（ADR-0008）不受影響。** 滑鼠停留預覽會顯示存放位置，但它只存在於內部頁；公開頁的展示品項轉換仍然把存放位置寫死為空，作為第二道防線。

**沒有任何後端變更**：不動 API、Domain、資料庫。

## Testing Decisions

好的測試只驗外部可觀察的行為，不碰內部狀態。這個專案既有的作法是 Angular TestBed 元件測試，透過 `data-*` 屬性選取 DOM 來斷言，而不是靠 CSS class 或直接讀元件私有欄位——沿用這個作法。

**接縫（3 個，其中 1 個是新增的）**

- **內部精選頁**（既有接縫）：頁籤依展示模式篩選、計數規則、無效與空頁籤退回、載入策略的續抓與終止、滑鼠停留的延遲與取消，**以及浮層的內容**（欄位組成、不顯示描述、圖片起手與退回）。
- **公開分享頁**（既有接縫）：頁籤行為與內部頁一致、以及存放位置不外洩的回歸測試。
- **頁籤列模組**（新增接縫）：鍵盤導覽、停用頁籤、roving tabindex、選中標示。

滑鼠停留預覽模組**刻意不給自己的接縫**——它的行為單純，透過內部精選頁這個較高的接縫驗證同樣涵蓋得到。頁籤列則保留獨立接縫：鍵盤導覽有 7 條測試，全部塞進頁面 spec 會讓它變成什麼都測的大雜燴。

實作時先給了浮層自己的 spec，後來合併回頁面層，並抽出一個「切到列表頁籤 → 停留 → 等過延遲」的 helper 收斂重複樣板。

**已知的測試陷阱（實作時真的踩到）**

- 拼貼牆只在「品項數多於格數」時啟動輪播。餵超過格數的資料給非 `fakeAsync` 的測試會建立真實的計時器，讓整個測試執行器永遠等不到結束。驗證格數時要餵剛好等於格數的資料量。
- 公開頁那條「存放位置不外洩」的回歸測試原本斷言焦點分區存在。頁籤化後預設不是焦點頁籤，這行會紅燈；為了消紅燈直接刪掉它，會讓底下真正的安全斷言變成假通過。正確作法是先切到焦點頁籤再斷言。
- 元件若要寫回網址就需要注入路由服務，測試的 provider 必須一併提供，否則注入失敗。
- 浮層測試合併到頁面層之後，測試資料開始帶圖片，於是預覽會真的建立圖片物件去預載原圖，而 `fakeAsync` 不會等它。目前無害（只掛了載入成功的處理，失敗靜默忽略）；若日後為浮層加上載入失敗的處理，這幾條測試可能開始噴非預期錯誤。

**涵蓋不到、需要真人操作的部分**：原圖載完後畫質是否真的提升、模糊填邊的實際觀感、鍵盤在真實瀏覽器的焦點跳轉、觸控裝置確實不觸發預覽、以及各斷點的版面。

## Out of Scope

- 任何後端變更（API、Domain、資料庫結構）。
- 分享者指定公開分享頁的預設頁籤。
- 庫存頁的滑鼠停留預覽——那頁是查找導向的，停留就跳大圖會干擾掃視。
- 觸控裝置的長按預覽。
- 預覽內的多圖瀏覽，多圖仍留在品項詳細頁。
- 拼貼牆格數依視窗寬度自適應。
- 焦點展品分區的高度調整——它是左圖右欄的並排版型，硬拉高只會讓右欄留白。

## Further Notes

不與任何既有 ADR 衝突。ADR-0007（展示模式與拼貼牆不受篩選）的語意完全保留，本次只改呈現方式，已在 ADR-0007 加上指向 ADR-0009 的後續連結。ADR-0008（存放位置永不公開）不受影響。

詞彙沿用專案詞彙表：精選、展示模式、品項、品類。詞彙表的「展示模式」條目已補上頁籤語意，明確記載頁籤是篩選器而非版型選擇器——這個誤讀一旦發生，會直接讓品項的展示模式欄位變成死欄位。
